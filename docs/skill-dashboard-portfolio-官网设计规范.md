# Skill Dashboard 官网设计规范

更新时间：2026-04-26  
适用范围：

- `skill-dashboard-portfolio-cn.html`
- 后续官网化展示页
- 项目作品集页
- 产品介绍页与提案页

---

## 1. 设计目标

本规范用于统一 Skill Dashboard 对外展示类页面的视觉与文案标准，确保：

- 页面具有一致的品牌气质
- 产品经理作品集表达清晰
- 页面既可用于展示，也可用于讲述
- 后续扩展新页面时不需要重新定义风格

---

## 2. 品牌设计原则

### 2.1 品牌气质关键词

- 清晰
- 克制
- 系统化
- 有产品感
- 有编辑感
- 不浮夸

### 2.2 应避免的方向

- 过度科技蓝紫风
- 大面积营销式发光
- 过强的创业路演味
- 过于“设计炫技”的视觉语言
- 卡片过多、层次混乱

### 2.3 品牌表达原则

Skill Dashboard 不是“卖一个 AI 梦想”，而是“帮助用户看清和管理已经拥有的 AI 资产”。  
因此页面表达应该围绕：

- 已有能力
- 结构化认知
- 资产治理
- 产品边界
- 系统可信度

## 3. 配色规范

### 3.1 主色板

| 色彩角色 | HEX | 使用场景 |
|---|---|---|
| 主深色 | `#22314A` | Hero 主背景、深色标题、重点结构层 |
| 次深色 | `#31486D` | Hero 渐变、副层深色 |
| 主强调色 | `#C96A5A` | 品牌强调、标签、导航激活、关键提示 |
| 强调浅色 | `#DE8A78` | 柔和高光、点缀态 |
| 页面背景 | `#F5EFE6` | 大页面暖底 |
| 卡片背景 | `#FFFDF9` | 实体卡片、正文承载层 |
| 主文字 | `#2B3445` | 主标题、正文 |
| 次文字 | `#667085` | 描述性文案 |

### 3.2 辅助色

| 颜色 | HEX | 语义 |
|---|---|---|
| 蓝 | `#6C8DB8` | 结构、平台、信息层 |
| 绿 | `#6E9C82` | 安全、治理、完成 |
| 紫 | `#8F79BA` | 智能、语言层、翻译层 |
| 橙 | `#C9964F` | 提示、流程、分析层 |

### 3.3 色彩使用比例建议

- 60%：浅色背景与纸感区域
- 25%：主文字与结构深色
- 10%：辅助功能色
- 5%：强调色

### 3.4 使用禁忌

- 不要让红色大面积铺满背景
- 不要同时使用高饱和蓝、紫、红做主角
- 不要把功能辅助色用成品牌主色

---

## 4. 渐变与背景规范

### 4.1 Hero 背景

推荐渐变：

```css
linear-gradient(140deg, #22314A 0%, #2B3F60 52%, #31486D 100%)
```

允许叠加：

- 陶土红高光雾层
- 浅蓝冷光雾层
- 低透明度网格纹理

### 4.2 正文背景

推荐渐变：

```css
linear-gradient(180deg, #FAF6F0 0%, #F5EFE6 42%, #F2ECE3 100%)
```

### 4.3 背景原则

- Hero 偏深、偏系统
- 正文偏浅、偏阅读
- 首屏与正文必须有过渡策略

---

## 5. 字体规范

### 5.1 标题字体

- `DM Serif Display`
- 中文回退：`Songti SC`

适用：

- Hero 大标题
- Section 标题
- 大数字与重点标题

### 5.2 正文字体

- `DM Sans`
- 中文回退：`PingFang SC`, `Microsoft YaHei`

适用：

- 正文
- 卡片描述
- 导航
- 标签说明

### 5.3 字号规范

| 层级 | 建议大小 |
|---|---|
| Hero 标题 | `clamp(3rem, 6vw, 5.1rem)` |
| 区块标题 | `clamp(2rem, 4vw, 2.9rem)` |
| 区块副标题 | `1rem - 1.06rem` |
| 正文 | `0.92rem - 1rem` |
| 标签 | `0.74rem - 0.85rem` |

### 5.4 字体原则

- 标题负责气质
- 正文负责可读性
- 不使用太多字体层级
- 中英文混排时优先稳重而不是炫技

---

## 6. 栅格与布局规范

### 6.1 页面宽度

- 主容器：`1160px`
- 页面横向内边距：`24px`

### 6.2 区块间距

- 标准区块上下留白：`88px`
- 移动端：`72px`

### 6.3 栅格规范

- Hero：双栏
- 功能区：3 栏
- 问题卡 / 指标卡：4 栏
- 决策区：2 栏
- 移动端统一收束为单列

### 6.4 布局原则

- 先大结构，再小细节
- 一屏只表达一个中心任务
- 卡片数量不要过载
- 不要在同一区块里混太多视觉逻辑

---

## 7. 卡片与组件规范

### 7.1 基础卡片

- 白底或暖白底
- 圆角：`20px`
- 轻阴影
- Hover 轻上浮

### 7.2 指标卡

- 用于 Hero
- 可带半透明玻璃感
- 内容必须短，不适合长段说明

### 7.3 功能卡

- 标题 + 描述 + 功能标签
- 每张卡只讲一个能力点

### 7.4 用户故事卡

- 左侧强调色竖条
- 三段式表达：
  - 作为谁
  - 我希望
  - 以便

### 7.5 架构图卡

- 分层
- 中英混排可接受
- 结构优先，不追求复杂图解

---

## 8. 页面结构规范

### 8.1 推荐顺序

1. Hero
2. Problem Statement
3. Target Users
4. Alpha Closed Loop
5. User Stories
6. Key Features
7. Product Decisions
8. Technical Architecture

### 8.2 结构原则

- 先讲问题，再讲方案
- 先讲用户，再讲功能
- 先讲取舍，再讲技术

### 8.3 不推荐的结构

- 一上来先堆功能
- 把技术架构放得过早
- 页面一开始就像操作后台

---

## 9. 文案规范

### 9.1 文案风格

- 面试友好
- 产品视角
- 逻辑清楚
- 不说空话

### 9.2 文案应强调

- 用户问题
- 产品洞察
- Alpha 闭环
- 产品边界
- 关键取舍

### 9.3 文案应避免

- “领先”“颠覆”“赋能”类空泛词
- 过度夸张的营销句式
- PRD 原文式大段堆砌
- 看起来像 AI 自动生成的空心表达

### 9.4 推荐句式

- 这个项目想解决的是……
- 用户真正缺少的不是……
- 第一版刻意不做……
- 技术结构服务于……

---

## 10. 动效规范

### 10.1 推荐动效

- 滚动显现
- 导航锚点高亮
- 卡片轻浮起

### 10.2 动效原则

- 动效只服务阅读
- 不抢叙事节奏
- 不做大幅度视差
- 不做复杂粒子或无必要动画

---

## 11. 响应式规范

### 11.1 桌面端

- 双栏 Hero
- 多栏卡片网格
- 区块留白较大

### 11.2 移动端

- 全部改为单列
- 文字优先可读
- Hero 不保留过于复杂的左右结构

### 11.3 响应式原则

- 优先保证阅读流畅
- 不强行保留桌面视觉效果
- 文案长度要提前考虑小屏阅读

---

## 12. 未来扩展规范

后续如果扩展更多页面，建议统一以下模块：

- 按钮系统
- 标签系统
- 图标系统
- CTA 文案系统
- 模块标题格式
- 页面底部说明格式

推荐扩展页面：

- Overview 产品主页
- Analysis 结构分析页
- Organize 整理工作台介绍页
- Skill Detail 详情页样例

---

## 13. 质量检查清单

上线或交付前检查：

- [ ] 首屏是否一眼能理解项目是什么
- [ ] Hero 与正文过渡是否自然
- [ ] 区块标题是否清晰
- [ ] 文案是否过长
- [ ] 卡片数量是否过载
- [ ] 配色是否统一
- [ ] 技术架构是否与产品叙事一致
- [ ] 移动端是否可读

---

## 14. 当前规范结论

当前这套页面最适合走的路线是：

`深蓝系统感 + 暖纸作品集感 + 陶土红产品强调`

它更像一份：

- PM 面试作品集
- 产品案例展示页
- 有完成度的单页讲述材料

而不是：

- 纯科技营销官网
- 炫技型视觉演示页

一句话总结：

`它应该像一个有判断力的产品项目，而不是一个想用视觉压住内容的首页。`
